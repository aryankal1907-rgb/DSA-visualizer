PRIORITY QUEUE USING A SORTED LINKED LIST (ALGORITHM ONLY, NO CODE)
Case study: a hospital waiting list with capacity 5, starting empty.
Operations used: enqueue, dequeue, peek, overflow, underflow, display


==================================================================================
0. WHAT IS A PRIORITY QUEUE?
==================================================================================
Idea : In a normal queue, the first one in is the first one out. In a priority
       queue, the MOST URGENT item comes out first, no matter when it arrived.
       If two items are equally urgent, the one that came first goes first.

Our rule : a SMALLER priority number means MORE urgent (1 is the most urgent).
           (To flip the rule, only the comparison in step 3 and 4 of enqueue changes.)

How we store it:
   A linked list that is always kept SORTED by priority. The most urgent node is
   always at the head, so removing the most urgent item is quick.

Each node has three parts:
+----------+-----------------------------------------------------------+
| Part     | Meaning                                                   |
+----------+-----------------------------------------------------------+
| data     | the value stored (for example a patient name)             |
| priority | a number: SMALLER number = MORE urgent (1 is most urgent) |
| next     | the address of the following node                         |
+----------+-----------------------------------------------------------+

The queue keeps three things:
+----------+------------------------------------------------------------------+
| Name     | Meaning                                                          |
+----------+------------------------------------------------------------------+
| head     | pointer to the first node = the most urgent item (NULL if empty) |
| size     | how many nodes are in the queue right now                        |
| capacity | the largest size we allow (5 in our example)                     |
+----------+------------------------------------------------------------------+

Picture of the queue after all 5 patients have arrived:

   head
    |
    v
  [Anu,1] ---> [Mia,1] ---> [Sam,2] ---> [Ravi,3] ---> [Dev,3] ---> NULL
  most urgent                                           least urgent


==================================================================================
1. HELPER CHECKS
==================================================================================
isEmpty : the queue is empty when size = 0 (head is NULL).
isFull  : the queue is full when size = capacity.

UNDERFLOW = trying to remove or read from an EMPTY queue.
OVERFLOW  = trying to add to a FULL queue.


==================================================================================
2. ENQUEUE (insert in the correct place)
==================================================================================
Idea : Do not add at the end. Find the right spot by priority and insert there, so
       the list stays sorted.

STEPS
1. Check isFull.
   If size = capacity, print OVERFLOW and stop.
   Why     : We must not add more nodes than the queue allows.
   Example : The queue is full (size 5) and Zed (priority 2) arrives: OVERFLOW.

2. Create a new node and store the data and the priority in it.
   Why     : The value and its urgency must travel together.

3. If the queue is empty, OR the new priority is SMALLER than the head's priority:
      a) set new.next = head
      b) set head = new node
   Why     : The new node is more urgent than everyone, so it goes to the front.
   Example : Queue is Ravi(3). Anu(1) arrives. 1 is smaller than 3, so Anu
             becomes the new head.

4. Otherwise (the new node belongs somewhere after the head):
      a) set current = head
      b) while current.next is not NULL AND current.next.priority <= new priority:
            move current forward (current = current.next)
      c) set new.next = current.next
      d) set current.next = new node
   Why     : We walk past every node that is more urgent OR equally urgent. That
             is why we use "<=" (less than or equal): a node with the same
             priority that arrived EARLIER must stay in front. (First come,
             first served.)
   Example : Queue is Anu(1) Sam(2) Ravi(3). Dev(3) arrives. We walk past Anu, Sam
             and Ravi (3 <= 3 is true) and insert Dev at the end.
   Order matters: do (c) before (d). If you do (d) first, you lose the address
   of the rest of the list.

5. Increase size by 1.

Time: O(n), because we may walk through the whole list.


==================================================================================
3. DEQUEUE (remove the most urgent item)
==================================================================================
Idea : The most urgent item is always at the head, so we remove the head.

STEPS
1. Check isEmpty.
   If size = 0, print UNDERFLOW and stop.
   Why     : There is nothing to remove.

2. Let temp = head.
   Why     : We need to remember the old head so we can delete it after moving on.

3. Save temp.data in a variable called value.
   Why     : We must return the value after the node is deleted.

4. Set head = head.next.
   Why     : The second node becomes the new most urgent item. If there was only
             one node, head becomes NULL and the queue is empty again.

5. Delete temp.

6. Decrease size by 1 and return value.
   Example : Queue Anu(1) Mia(1) Sam(2) Ravi(3) Dev(3). Dequeue returns Anu.
             Mia becomes the new head.

Time: O(1)


==================================================================================
4. PEEK (look at the most urgent item without removing it)
==================================================================================
STEPS
1. Check isEmpty. If size = 0, print UNDERFLOW and stop.
   Why     : An empty queue has no urgent item.

2. Return head.data (and head.priority if you want to show it).
   Example : Peek returns Anu. The queue does not change.

Time: O(1)


==================================================================================
5. TRAVERSE AND DISPLAY
==================================================================================
Idea : TRAVERSE means visiting every node exactly once, from the head (most
       urgent) to the tail (least urgent). DISPLAY is a traverse where the action
       at each visit is "print the name and the priority".
       This list ends with NULL, so we stop when current becomes NULL.

TRAVERSE STEPS
1. Check isEmpty.
   If size = 0, print "Queue is empty" and stop.
   Why     : There are no nodes to visit.

2. Set current = head.
   Why     : The visit starts at the most urgent item.

3. While current is NOT NULL, repeat:
      a) do the action on current (print it, count it, and so on)
      b) move forward: current = current.next
   Why     : Each round visits one node and moves to the next one.

4. When current becomes NULL, stop.
   Why     : NULL means we have gone past the last node, so every node was visited.

DISPLAY STEPS (the same loop, with a nicer print)
   Keep a counter called rank, starting at 1. At each visit, print:
      rank, data, priority      and then add 1 to rank
   Example output:
      1. Anu  (priority 1)
      2. Mia  (priority 1)
      3. Sam  (priority 2)
      4. Ravi (priority 3)
      5. Dev  (priority 3)
   Why this is useful: the list is already sorted by priority, so a plain
   traverse shows the order in which patients will be served. No extra sorting
   is needed.

Trace for the queue Anu(1) Mia(1) Sam(2) Ravi(3) Dev(3) (display):
+-------+---------+---------------------------+--------------+
| Round | current | Action (print)            | Next current |
+-------+---------+---------------------------+--------------+
| 1     | Anu(1)  | print 1. Anu, priority 1  | Mia(1)       |
| 2     | Mia(1)  | print 2. Mia, priority 1  | Sam(2)       |
| 3     | Sam(2)  | print 3. Sam, priority 2  | Ravi(3)      |
| 4     | Ravi(3) | print 4. Ravi, priority 3 | Dev(3)       |
| 5     | Dev(3)  | print 5. Dev, priority 3  | NULL, stop   |
+-------+---------+---------------------------+--------------+

Same loop, different action:
+---------------------------+--------------------------------+--------------------------+
| What you want             | Action at each visit           | Result                   |
+---------------------------+--------------------------------+--------------------------+
| Display                   | print rank, data, priority     | Anu, Mia, Sam, Ravi, Dev |
| Count the nodes           | add 1 to a counter             | 5                        |
| Count priority-1 patients | add 1 only if priority = 1     | 2                        |
| Find the tail (last node) | stop when current.next is NULL | Dev(3)                   |
+---------------------------+--------------------------------+--------------------------+

Different queue sizes:
+----------------+--------------------------------------------------+
| Queue          | What happens                                     |
+----------------+--------------------------------------------------+
| empty          | Print "Queue is empty" and stop                  |
| one node (Dev) | Visit Dev, then next is NULL, stop after 1 visit |
| five nodes     | Visit all 5, then stop at NULL                   |
+----------------+--------------------------------------------------+

Time : O(n), one visit per node
Space: O(1), only the pointer called current is needed
Note : Traverse and display do NOT change the queue. Nothing is removed.


==================================================================================
6. DRY RUN (case study, capacity 5)
==================================================================================
Reading the Queue column: Name(priority), the head is on the left.

+------+----------------------+-------------------------------------+------+
| Step | Operation            | Queue (head to tail)                | Size |
+------+----------------------+-------------------------------------+------+
| 0    | Start                | empty                               | 0    |
| 1    | enqueue Ravi, p=3    | Ravi(3)                             | 1    |
| 2    | enqueue Anu, p=1     | Anu(1) Ravi(3)                      | 2    |
| 3    | enqueue Sam, p=2     | Anu(1) Sam(2) Ravi(3)               | 3    |
| 4    | enqueue Dev, p=3     | Anu(1) Sam(2) Ravi(3) Dev(3)        | 4    |
| 5    | enqueue Mia, p=1     | Anu(1) Mia(1) Sam(2) Ravi(3) Dev(3) | 5    |
| 6    | enqueue Zed, p=2     | OVERFLOW, no change                 | 5    |
| 7    | peek (returns Anu)   | Anu(1) Mia(1) Sam(2) Ravi(3) Dev(3) | 5    |
| 8    | dequeue (gives Anu)  | Mia(1) Sam(2) Ravi(3) Dev(3)        | 4    |
| 9    | dequeue (gives Mia)  | Sam(2) Ravi(3) Dev(3)               | 3    |
| 10   | dequeue (gives Sam)  | Ravi(3) Dev(3)                      | 2    |
| 11   | dequeue (gives Ravi) | Dev(3)                              | 1    |
| 12   | dequeue (gives Dev)  | empty                               | 0    |
| 13   | dequeue              | UNDERFLOW, no change                | 0    |
+------+----------------------+-------------------------------------+------+

Look closely at step 5: Mia(1) goes AFTER Anu(1) because Anu arrived first, but
BEFORE Sam(2) because 1 is more urgent than 2.

Order in which the patients were served: Anu, Mia, Sam, Ravi, Dev
Order in which they arrived            : Ravi, Anu, Sam, Dev, Mia
A normal queue would have served them in the arrival order. Compare the two lists
to see what the priority changed.

7. SPECIAL CASES
==================================================================================
+-----------+---------------------------------------+------------------------------------------------+
| Operation | Situation                             | What to do                                     |
+-----------+---------------------------------------+------------------------------------------------+
| Enqueue   | Queue is full                         | Print OVERFLOW and stop                        |
| Enqueue   | Queue is empty                        | New node becomes head                          |
| Enqueue   | New priority is smaller than the head | New node becomes head                          |
| Enqueue   | Same priority as existing nodes       | Place it AFTER them (first come, first served) |
| Dequeue   | Queue is empty                        | Print UNDERFLOW and stop                       |
| Dequeue   | Only one node in queue                | Free it, then head becomes NULL                |
| Peek      | Queue is empty                        | Print UNDERFLOW and stop                       |
+-----------+---------------------------------------+------------------------------------------------+


==================================================================================
8. COMPLEXITY
==================================================================================
+---------------------------+------+-------------+
| Operation                 | Time | Extra space |
+---------------------------+------+-------------+
| Enqueue (insert in order) | O(n) | O(1)        |
| Dequeue                   | O(1) | O(1)        |
| Peek                      | O(1) | O(1)        |
| isEmpty / isFull          | O(1) | O(1)        |
| Display                   | O(n) | O(1)        |
+---------------------------+------+-------------+
The queue itself uses O(n) space, one node per item.

Other ways to build a priority queue (just to know):
+---------------------------------+----------+----------+------+
| Way to build it                 | Enqueue  | Dequeue  | Peek |
+---------------------------------+----------+----------+------+
| Sorted linked list (our choice) | O(n)     | O(1)     | O(1) |
| Unsorted linked list or array   | O(1)     | O(n)     | O(n) |
| Heap (later topic)              | O(log n) | O(log n) | O(1) |
+---------------------------------+----------+----------+------+
Sorted list: slow to insert, fast to remove. Unsorted: the opposite.
A heap balances both, and you will meet it in the Heap topic.

9. PREDICT (try before you read the answer)
==================================================================================
Q1. The queue is Anu(1) Sam(2) Ravi(3). A new patient Leo arrives with priority 2.
    Where does Leo go?
A1. Between Sam(2) and Ravi(3). Leo is placed AFTER Sam because Sam arrived first
    and has the same priority.

Q2. The queue is Sam(2) Ravi(3). A new patient Kim arrives with priority 1.
    What happens?
A2. Kim becomes the new head, because 1 is smaller than the head's priority 2.

Q3. The queue has one node, Dev(3). After dequeue, what is head?
A3. NULL. The queue is empty, and the next dequeue prints UNDERFLOW.

Q4. The queue is full (size 5). What does enqueue do, even if the new patient has
    priority 1?
A4. It prints OVERFLOW. Urgency does not help when there is no space.

Q5. What is the time of dequeue, and why is it so quick?
A5. O(1). The most urgent item is always at the head, so no searching is needed.
