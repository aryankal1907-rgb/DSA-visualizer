SORTING ALGORITHMS (ALGORITHM ONLY, NO CODE)
Case study array for all three sorts: [29, 12, 35, 12, 7, 31, 18]
Correct sorted answer               : [7, 12, 12, 18, 29, 31, 35]


==================================================================================
1. COUNTING SORT
==================================================================================
Idea     : Do not compare elements. Count how many times each value appears, then
           use those counts to place every element directly in its final position.
Works for: Whole numbers (0 and above) in a small range.

STEPS
1. Find the maximum element (max).
   Why     : It decides how long the count array must be.
   Example : max = 35

2. Create a count array with indexes 0 to max and set every value to 0.
   Why     : Each index is a counter for one value.
   Example : 36 counters, all 0

3. Read the input once. For every value v, add 1 to count[v].
   Why     : This records the frequency of every value.
   Example : count[7]=1, count[12]=2, count[18]=1, count[29]=1, count[31]=1, count[35]=1

4. Make the counts cumulative: going left to right, add the previous counter
   into the current one.
   Why     : count[v] now means "how many elements are <= v". That is the END
             position of v in the sorted array.

5. Create an empty output array with the same size as the input.
   Why     : Sorted values go here, so the input stays safe while we work.

6. Read the input from RIGHT to LEFT. For each value v:
      a) put v at output position count[v] - 1
      b) reduce count[v] by 1
   Why     : Going right to left keeps equal values in their original order.
             This is called STABLE.

7. Copy the output array back into the original array.
   Result  : [7, 12, 12, 18, 29, 31, 35]

Step 4 table (cumulative counts, only values that appear)
+-------+-----------+------------------+
| Value | Frequency | Cumulative count |
+-------+-----------+------------------+
| 7     | 1         | 1                |
| 12    | 2         | 3                |
| 18    | 1         | 4                |
| 29    | 1         | 5                |
| 31    | 1         | 6                |
| 35    | 1         | 7                |
+-------+-----------+------------------+

Step 6 trace (reading right to left)
+------------+--------------+-----------------+-------------+
| Value read | count before | Output position | count after |
+------------+--------------+-----------------+-------------+
| 18         | 4            | 3               | 3           |
| 31         | 6            | 5               | 5           |
| 7          | 1            | 0               | 0           |
| 12 (2nd)   | 3            | 2               | 2           |
| 35         | 7            | 6               | 6           |
| 12 (1st)   | 2            | 1               | 1           |
| 29         | 5            | 4               | 4           |
+------------+--------------+-----------------+-------------+

PREDICT: Before step 6, what output position does 18 get?
ANSWER : 3, because count[18] = 4 and we use 4 - 1.


==================================================================================
2. BUCKET SORT
==================================================================================
Idea      : Split the values into groups (buckets) by range, sort each small
            group, then join the groups in order.
Works best: Values that are spread out fairly evenly.

STEPS
1. Find the maximum element and decide the number of buckets (b).
   Why     : The buckets must cover the whole range of values.
   Example : max = 35, choose b = 4

2. Create b empty buckets, numbered 0 to b - 1.
   Why     : Each bucket holds one range of values.
   Example : bucket 0, bucket 1, bucket 2, bucket 3

3. Choose the rule that picks the bucket:
      bucket = (value x b) / (max + 1), dropping the decimal part
   Why     : Smaller values go to lower buckets, so the order ACROSS buckets is
             already correct.
   Example : (value x 4) / 36, which is the same as value / 9

4. Read the input from left to right and put each value into its bucket.
   Why     : This is the distribution step.

5. Sort every bucket on its own (usually with insertion sort).
   Why     : Each bucket is small, so this is quick.
   Example : Only bucket 3 needs work: [29, 35, 31] becomes [29, 31, 35]

6. Join the buckets from bucket 0 to the last bucket.
   Why     : Bucket 0 holds the smallest values, so joining in order gives a
             sorted list.
   Example : [7] + [12, 12] + [18] + [29, 31, 35]

7. Copy the joined list back into the original array.
   Result  : [7, 12, 12, 18, 29, 31, 35]

Step 4 distribution
+-------+-------------+--------+
| Value | Calculation | Bucket |
+-------+-------------+--------+
| 29    | 29 / 9 = 3  | 3      |
| 12    | 12 / 9 = 1  | 1      |
| 35    | 35 / 9 = 3  | 3      |
| 12    | 12 / 9 = 1  | 1      |
| 7     | 7 / 9 = 0   | 0      |
| 31    | 31 / 9 = 3  | 3      |
| 18    | 18 / 9 = 2  | 2      |
+-------+-------------+--------+

Buckets after step 4
+--------+--------------+
| Bucket | Values       |
+--------+--------------+
| 0      | [7]          |
| 1      | [12, 12]     |
| 2      | [18]         |
| 3      | [29, 35, 31] |
+--------+--------------+

PREDICT: Which bucket would the value 26 go to?
ANSWER : Bucket 2, because 26 / 9 = 2.


==================================================================================
3. RADIX SORT (LSD: start from the last digit)
==================================================================================
Idea     : Sort the numbers digit by digit, starting from the ones place. After
           the ones, then the tens, and so on, the whole list is sorted.
Important: Every digit pass must be STABLE (equal digits keep their earlier
           order). Without that, the earlier work is destroyed.

STEPS
1. Find the maximum element.
   Why     : It tells you how many digits the biggest number has.
   Example : max = 35, so 2 digits, so 2 passes

2. Set the place value to 1 (the ones place).
   Why     : We start from the least significant digit.

3. Take the digit at this place of every number:
      digit = (value / place) mod 10
   Why     : This is the sorting key for this pass.
   Example : Ones digits are 9, 2, 5, 2, 7, 1, 8

4. Make 10 buckets (digits 0 to 9). Put each number into the bucket of its digit,
   in the order you read them.
   Why     : Reading in order keeps the pass stable.

5. Collect the buckets from digit 0 to digit 9 into one list.
   Why     : This list is the array after this pass.

6. Multiply the place value by 10.
   Why     : Move to the next digit on the left.

7. Repeat steps 3 to 6 until the place value is bigger than max.
   Why     : Then every digit has been processed.

8. The last collected list is the sorted array.
   Result  : [7, 12, 12, 18, 29, 31, 35]

Pass 1: ones digit (input order: 29, 12, 35, 12, 7, 31, 18)
+--------+------------+--------+
| Number | Ones digit | Bucket |
+--------+------------+--------+
| 29     | 9          | 9      |
| 12     | 2          | 2      |
| 35     | 5          | 5      |
| 12     | 2          | 2      |
| 7      | 7          | 7      |
| 31     | 1          | 1      |
| 18     | 8          | 8      |
+--------+------------+--------+
Collected: [31] [12, 12] [35] [7] [18] [29]
Array now: [31, 12, 12, 35, 7, 18, 29]

Pass 2: tens digit (a one-digit number like 7 has tens digit 0)
+--------+------------+--------+
| Number | Tens digit | Bucket |
+--------+------------+--------+
| 31     | 3          | 3      |
| 12     | 1          | 1      |
| 12     | 1          | 1      |
| 35     | 3          | 3      |
| 7      | 0          | 0      |
| 18     | 1          | 1      |
| 29     | 2          | 2      |
+--------+------------+--------+
Collected: [7] [12, 12, 18] [29] [31, 35]
Array now: [7, 12, 12, 18, 29, 31, 35]

PREDICT: After pass 1, which number comes first?
ANSWER : 31, because its ones digit is 1, the smallest.


==================================================================================
COMPLEXITY COMPARISON
(n = number of items, k = range of values, d = digits, b = base, usually 10)
==================================================================================
+----------------+------------+------------+------------+
|                | Counting   | Bucket     | Radix      |
+----------------+------------+------------+------------+
| Best/avg time  | O(n+k)     | O(n+k)     | O(d*(n+b)) |
| Worst time     | O(n+k)     | O(n^2)     | O(d*(n+b)) |
| Extra space    | O(n+k)     | O(n+k)     | O(n+b)     |
| Stable?        | Yes        | Yes*       | Yes        |
+----------------+------------+------------+------------+
* Bucket sort is stable only if the sort used inside each bucket is stable.

Best for  : Counting = small range of whole numbers
            Bucket   = evenly spread values
            Radix    = many numbers with a fixed number of digits
Weak point: Counting = wastes memory if max is huge (for example 1,000,000)
            Bucket   = slow if most values land in one bucket
            Radix    = needs a stable helper sort for each digit
